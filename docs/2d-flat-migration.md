# 2D 平面版：3D 功能迁移说明

`cosmic-collision-simulator.html` 现在是 `cosmic-collision-3d.html` 的二维对应版本。首页「2D 引力沙盒」入口与 URL 保持不变。

## 平面约束

迁移以「保持 2 维平面」为硬约束，已写入实现和测试（`tests/test_simulator.py` 的 `test_2d_flat_*` 系列）：

- 不加载 Three.js、不使用 WebGL、不引入 Z 轴或透视相机；页面只依赖 `celestial-size.js`、`planet-assessment.js`、`game-overlays.css` 和原生 Canvas 2D。
- 天体状态只有 `x / y / vx / vy / ax / ay`；相机只有 `cam = {x, y, zoom}`，支持右键或中键拖动平移、滚轮以光标为中心缩放、`Shift+滚轮` 调整质量倍率。
- 所有叠加层都画在平面上：希尔球与宜居带是虚线圆/环，奥尔特云是圆环点带，星环与吸积盘是椭圆，标签直接平面投影。
- 引力、碰撞、潮汐与动量守恒都在二维里计算，软化常数与 3D 版一致（`d² = dx² + dy² + 60`）。

## 恒星系预设的长期稳定

「单星系 / 双星系 / 三星系」三个按钮曾会在运行一会儿后飞散，原因有三层，已一并修复：

1. **初始条件错误**：旧版把整个相对速度给了伴星，主星又额外反向补偿，实际相对速度超标；三星还没有用内双星的总质量、也没做质心动量归零。现在照 3D 版构建：双星绕共同质心且速度按质量比分配；三星是紧密内双星 + 约 5 倍间距外的第三星（层级式三体），内外两部分动量互相抵消；恒星之间再做一次质心速度归零。
2. **碎片碰撞级联**：撞击碎片原先生成在幸存天体内部，下一帧立刻再次相撞，而潮汐剥离又每次再生成 3 颗彗星，形成指数级联，把主星从数量上限里挤掉。现在碎片出生在幸存半径之外、速度不低于逃逸速度，另有 10 帧碰撞宽限（`spawnGrace`）与碎片总数上限。
3. **共面长期混沌**：2D 全部共面，行星之间近距离相遇比 3D（带轨道倾角）频繁得多。预设轨道里的小天体标记为 `restricted` 测试粒子——照常受恒星引力，但不互相扰动、也不反作用于恒星；引力积分在少于 120 个天体时用 4 个子步。玩家手动发射的天体、希尔球演示里的卫星等仍是完整 N 体，不受影响。

实测手动积分 4000 步（约 1 分钟实时运行）：双星间距保持 149.4–150.6（初始 150），三星内双星 67.2–71.3（初始 70）、外伴星约 337（初始 340），三种系统均无合并、无抛失、行星留在轨道上。

## 星系盘面与并合

星系、星团与暗物质晕是弥散的扩展天体，不能直接套用恒星的 `∛质量 × rk` 半径。旧版在「易观察」模式下给 2400 质量星系约 `16066` 的物理半径，但绘制时又把视觉半径截断到 `180`，导致：两个星系一生成就重叠合并、并合后看起来像一颗恒星、`pickBody()` 的点击命中半径几乎吞掉整个画布。现在 `radiusFor()` 给这些类型单独的有界二维盘面半径（星系基准 150、星团 90、暗晕 185），绘制、点选与碰撞共用同一个 `b.r`。

`demoGalaxyCollision()` 让两个半径约 150 的星系从中心距约 480（间隔约 181）处相向靠近，并先把视图缩放到 `0.62`，因此放置或演示时都能看到完整旋臂。`handleCollisions()` 对星系与星系使用专用并合分支：合并双方盘面星点，记录并合朝向并做 3.2 秒潮汐拉伸动画，生成星云与冲击波，但不再抛射普通恒星碎片或彗星。实测手动积分到并合：只剩一个 `galaxySpiral`，质量 4800、半径约 189、盘面点 159 个，零碎片与彗星。

## 登陆星球

两版都在控制面板顶部常驻「🛬 登陆星球」。共享的 `planet-assessment.js` 在折叠移动端控制时保留 `#landBar`、`a`、`h1` 与 `#featuredTools` 在 `#panelControls` 之外，因此即使面板收起，登陆入口仍然可见；收起状态下也提供了紧凑按钮样式。

2D 仍是纯 Canvas 2D：打开 `#surfaceView` 覆盖层，选中天体居中并轻微放大，地平线从画面底部升到 62%，按类别绘制岩石、气态云顶、恒星、致密星、强引力场或弥散星群的二维地表纹理，同时显示天体资料卡。返回轨道时恢复原相机与进入前的暂停状态。实现见 `openLanding()` / `closeLanding()` / `drawLanding()`，并挂载在 `#btnLand`、`#btnLeaveSurface` 与 Esc 键。

3D 复用同一资料卡结构：`landingPose()` 把相机停在 `1.08 × 天体半径` 处，以表面法线为 `up`、视线切向球面并略微下俯，形成可见弧形地平线；降落与返回都有相机动画。观察期间隐藏距离网格、轨迹、希尔球、选中环与主控制面板，返回后恢复原相机姿态、暂停状态与辅助线。黑洞、恒星、气态巨行星和星系等没有固体表面的对象会显示对应的科学说明。

## 质量标签与希尔球示意范围

两版在「显示标签」区新增 `#massLabelsToggle`（默认开启）：2D 在 `drawLabels()` 里把 `⚖ 质量 <数值>` 画成标签第二行，3D 在 `updateMeasurements()` 里用 `<span class="label-mass">` 作为名字下方第二行。两版共用同一套数值口径 `formatLabelMass()`：小于 0.01 或大于等于 1e6 用科学计数法，其余按 2 位小数/1 位小数/整数分级。3D 标签的水平避让宽度只按第一行测量，所以开启质量标签不会挤掉相邻标签（`test_crowded_labels_do_not_overlap` 的可见数量在开关前后一致）。关闭开关只隐藏质量，类型与距离文本照常显示。

开关下方的 `#massUnitSelect` 下拉默认「**自动（按天体）**」：恒星、致密星、黑洞、星团标太阳质量，行星标地球质量，气态巨行星、褐矮星与环行星标木星质量，星系与暗物质分布标银河系质量，小行星、彗星、探测器标千克——不再千篇一律用太阳质量。也可手动固定为银河系质量、太阳质量、木星质量、地球质量、月球质量、海洋质量、大气质量、千克、克、毫克或游戏单位。

换算按**每种类型的现实典型质量**锚定（`TYPE_REAL_MASS`，两版逐字一致）：「一个标准天体」（`TYPES[type].base` 游戏质量）对应现实中的典型值——恒星 600 = 1 太阳质量、行星 40 = 1 地球质量、气巨 70 = 1 木星质量、环行星 55 = 0.3 木星质量（土星级）、褐矮星 90 = 50 木星质量、旋涡星系 2400 = 1 银河系质量（椭圆 1e12、不规则 1e9 太阳质量）、中子星 6000 = 1.4 太阳质量、白矮星 3000 = 0.6 太阳质量、黑洞 2500 = 10 太阳质量、类星体 12000 = 1e8 太阳质量、疏散星团 1000 = 200 太阳质量、球状星团 2000 = 1e5 太阳质量、小行星 3 = 1e20 千克、彗星 2 = 1e14 千克、探测器 0.02 = 1 吨。质量偏离标准值时现实质量等比缩放（如双倍恒星 = 2 太阳质量）。`realMassKg()` 做这一步换算，缺失类型回退到 `MASS_FAMILY_ANCHORS` 族锚。手动选择某一单位时所有天体都用同一千克基准（如恒星 600 = 1 太阳质量 = 约 33.3 万地球质量），切换单位不会自相矛盾；数值沿用 `formatLabelMass()` 的分级格式，极大/极小自动转科学计数法。

`estimateHillSphere()` 现在对**所有**选中天体都返回一个可绘制的半径。严格路径保持不变：有引力束缚的较重主星时按 `r = d·∛(m/3M)` 计算希尔半径，质量比过大时改用双体 L1 距离。严格路径失败（孤立天体、高速飞掠、只有更轻伴星等）时返回 `method: 'illustrative'` 的**有界示意半径** `clamp(max(∛m·26, r·2.6), 8, 420)`：它只按天体自身质量与半径标度，**不使用到参考天体的距离**，因此飞掠天体不会像真实希尔球那样随距离膨胀成巨大圈；`primary` 为 null，信息栏明确写「示意范围……不是真实希尔球、不代表稳定轨道」。两版都给示意圈单独的视觉上限（2D 为 `150 / cam.zoom`，3D 为相机距离的 0.55 倍），避免撑满画布。图形仍只用于显示，不参与引力与碰撞。

## 没有直接平移的 3D 能力

真实三维轨道倾角、透视景深、球面纹理与法线贴图、GPU 后处理、DOM 标签的透镜反投影。这些是渲染层特性，不影响二维下的物理与玩法。

## 保持兼容的行为

- 控件 id、统计字段、`#btnShockwave` 重播/停止、`#nextPlanet`、`#toggleControls` 移动端折叠、评估面板全部保持原样。
- `randomSystem()` 仍生成最多 9 个天体；`?scene=shockwave` 仍每 3 秒重播、暂停冻结冲击波、清空后停止。
- 脚本仍为传统 `<script>`（非 module），顶层绑定可供 Playwright 直接读取。
