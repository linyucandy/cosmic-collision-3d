# 游戏发布与评价社区

用户选择首版通过提交游戏网址发布。保留现有宇宙游戏及静态入口，新增游戏广场、发布/编辑页、游戏详情与评价交流页。

## 用户提供托管地址后的最终决定

用户提供现有 GitHub Pages 与 GitHub 仓库，并明确选择“使用 GitHub 账号发布和评价，继续用当前网址”。因此线上默认使用 GitHub Issues 作为共享记录源：网页准备带结构标记的草稿，由用户在 GitHub 确认提交。读取公开 Issues 汇总作品和评分，GitHub 评论承载交流，无服务器密钥或站内密码。原站内账号后端保留为本地及独立服务器的可选方案，与线上记录独立。

作品信息仅接受 HTTP/HTTPS 网址和受限长度文本，作者以实际 GitHub 提交账号为准；同一账号同一游戏取最新有效评价，排除作者自评。关闭作品 Issue 下架，编辑原帖修改作品。草稿生成不宣称已发布，读取失败或分页无法完整载入不显示部分评分。页面提供同步与直接访问原帖入口。

GitHub Pages 使用相对项目路径，保留当前线上网址；无需部署 Python 才能参与。公开读接口有缓存与访问限制，明确显示错误和原帖回退。线上测试不会自动创建测试帖子。

## 方案

采用同源 Flask API + SQLite + 现有原生 HTML/JS，并以 Waitress 启动。相比仅使用浏览器 localStorage，该方案能让不同账户及浏览器共享同一份数据；相比接入外部云服务，不需要用户预先提供账号和密钥。公网使用需要将服务部署到可访问的服务器，GitHub 静态托管不能运行该后端。

## 功能与界限

- 游客浏览、搜索、分类、按评分/时间排序，打开游戏网址及阅读评价和回复。
- 用户注册登录后可发布游戏，编辑、下架、重新上架自己的作品。
- 游戏以 HTTP/HTTPS 网址发布，不接收 HTML/ZIP，也不在本站执行第三方游戏代码。
- 每个账户对每个游戏保留一条 1–5 星评价，可修改或删除；评分始终来自数据库聚合。作者不为自己评分，可回复玩家交流。
- 评价下可回复交流、删除自己的回复。未登录时明确引导登录，网络错误提供重试；静态预览不会伪装成已发布成功。
- 默认只展示现有两个真实游戏，不伪造作品、评价、评分或用户人数。

## 数据与身份

SQLite 保存用户、散列密码、到期会话、游戏、评价和回复。私有数据目录不进入 Git，也不通过静态路由暴露。会话用 HttpOnly/SameSite Cookie，写入验证 CSRF、来源和身份；服务器验证长度、评分、URL 协议和作者归属。用户内容以文本渲染，外部游戏仅在新标签打开。

## 界面

沿用深色太空风格；首页新增游戏广场与发布入口，模拟器返回首页仍可用。社区有注册/登录弹窗、清晰的空状态及移动布局。游戏详情显示真实平均分、评分分布、评价与回复；发布页展示网址、类型、名称及介绍。

## 验证与交付

测试跨账户发布、数据持久化、重复评分更新、平均分、回复、权限、下架、输入校验与私有文件保护。浏览器验证完整发布—评价—回复流程、搜索筛选及手机布局，并跑原游戏回归。提交并推送代码，启动可访问的本地服务；公网部署与账号邮件恢复不包含在本次默认实现中。
